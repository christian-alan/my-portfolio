## The Component 

The purpose of the drop-down component is for the user to pick the person to who they 
intend to wire the money. The options are presented to the user in a chip-like format, 
where the chip anatomy of the chip is essentially the user’s picture and their name 
wrapped in a thinly bordered container. 

As the user clicks on the select field, a drop-down menu opens and the user is presented 
with all the possible options attheir disposal by the system. Finally, the user is prompted 
to select one of the options and move on to the rest of the input fields.

## Technical Breakdown 

The component follows a simple notion of feeding a dataset to the component, processing 
the data through the component logic with the designed interaction, and eventually 
returning the result after the interaction.

### Vue Template

```html
<template>
    <div class="contact-drop-down">
        <!-- Button -->
        <button id="contact-btn" @click="$emit('dummy-event')">

            <span v-if="picked === null" id="default-contact" class="text-sm text-gray-400">-- Select a contact --</span>
            <span v-if="picked != null" id="contact-chip" class="contact-chip">
                <img height=24 width=24 class="object-cover rounded-full h-6 w-6 important" :src="contacts[picked].src"
                    alt="profile picture" />
                {{ contacts[picked].name }}
            </span>
            <!-- Drop down arrow -->
            <span>
                <svg width="24" height="24" viewBox="0 0 24 24" fill="none" xmlns="http://www.w3.org/2000/svg">
                    <path d="M12 15L7 10H17L12 15Z" fill="#1D1B20" />
                </svg>
            </span>
        </button>

        <!-- Drop down menu -->
        <ul id="contact-drop-down-menu">
            <li v-for="(contact, index) in contacts"
                :class="index === picked ? 'bg-gray-50 border-[0.5px] border-gray-200' : ''">
                <div>
                    <input type="radio" :id="index" :value="index" v-model.lazy="picked" />
                    <label :for=index>
                        <img height=32 width=32 class="object-cover rounded-full h-8 w-8 important" :src=contact.src
                            alt="profile picture" />

                    </label>
                </div>


                <span v-if="index === picked">
                    <svg width="18" height="18" viewBox="0 0 18 18" fill="none" xmlns="http://www.w3.org/2000/svg">
```

### Vue scripts
``` javascript
<script>
import { ref } from 'vue'
import { contactIndex  } from '../store/store';
export default {
    props: {
        contacts: [{
            src: String,
            value: String,
            name: String
        }]
    },
    data() {
        return {
            picked:ref(null)
        }
    },
    watch:{
        picked(newValue,oldValue){
            if(newValue!=null) {
                // Push the value into a local store
                contactIndex.set(newValue)
            }
        }
    }
}
</script>
```

## Challenges
### Why I had to choose another framework?

One of the framework rules set by the Astro teams is that developers cannot use
the client-side script to make changes in the DOM element. I ran into the issue when updating 
the span ID as a contact chip within the button. In the component, when the user picks a contact,
the user-picked contact has to be displayed within the button. This type of change requires the 
client-side script to have control over the DOM. However, when it comes to Astro, only the 
server-side script exercises control over the DOM, which is one of the primary constraints ingrained 
in the framework. This constraint begs the developer to turn to other frameworks to bypass it. 
In this case, I chose vue.


### Missing features
At every step, I saw Astro winning my heart, from having one-line commands for 
third-party integrations like vue, and tailwinds. Etc. At my disposal to had a super concise 
way of implementing JSX-like looping and conditionals statements into my HTML code, until I 
ran into the use case of listening to the events published by my cute vue-component. At first, 
I felt betrayed. The Astro team gave the provision of passing props into the external framework components, 
yet they didn’t provide any way to listen to events published from within these components. 
Why on earth would they do that? I spent that whole afternoon wallowing in my existential 
dread and cussing Astro for partially changing my life. Until I ran into the idea of storing 
the return value in an external store. It worked! But it wasn’t that great of a solution. 
In a way, it sounds a bit stupid to store the return value of the component in a store and
access that store on the parent level of the component. But I guess, it is what it is. 
You can't have everything. But maybe one day!
